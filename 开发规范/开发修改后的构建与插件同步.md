# 开发修改后的构建与插件同步

## 推荐流程

1. 完全关闭 Alife。主窗口最小化到托盘不算退出。
2. 在仓库根目录运行 `BuildAndSyncDev.bat`。
3. 构建成功后，运行根目录的 `Alife.Client.exe.lnk`。

也可以运行 `BuildAndSyncDev.bat /run`，在成功后自动启动该快捷方式。

脚本会先把动态插件同步到开发目录，再完整构建 Debug Client。构建输出位于：

```text
D:\AlifeFork\Outputs\Debug
```

## 两类模块的区别

### 官方源码模块

路径：

```text
sources\Alife.Function\...
```

例如 Fish Audio、Speech、Auditory 和 ChatRoom。这类模块在 Debug Client 中通过项目引用构建，修改后必须完整构建 `Alife.Client.csproj`。它们不需要复制到 `PluginsDebug`，同步脚本会主动跳过，以免同一模块被加载两次。

如果新增了一个没有 UI 引用链的官方模块，还要确认 `sources\Alife\Alife.Client\Program.cs` 在 Debug 加载列表中显式引用了该模块，否则 DLL 虽然生成，模块管理仍可能扫描不到。

### 动态安装插件

路径：

```text
Storage\Plugins\...
Plugins\...
```

这类插件需要通过 `SyncPluginsToDev.bat` 同步到：

```text
Storage\PluginsDebug
```

同步脚本优先使用仓库根目录的 `Storage`；仓库没有该目录时，才回退到 `%USERPROFILE%\Documents\Alife\Storage`。

## 根目录快捷方式

`Alife.Client.exe.lnk` 当前执行：

```text
dotnet run --project D:\AlifeFork\sources\Alife\Alife.Client\Alife.Client.csproj --launch-profile app -c Debug
```

因此它会运行 Debug Client，并在需要时自动构建。不过，如果旧的 Alife 进程仍在运行，新进程可能因为单实例窗口或文件占用而退出，旧进程也不会自动加载刚修改的 DLL。开发修改后应先完全退出，再执行一键脚本或重新运行快捷方式。

## Fish Audio 修改检查

Fish Audio 的源码位于：

```text
sources\Alife.Function\Alife.Function.Speech.FishAudio
```

只构建 Fish Audio、Speech 或测试项目，会更新对应模块输出，但不能保证正在运行的 Client 已换用新程序集。完成修改后应运行：

```text
BuildAndSyncDev.bat
```

然后重新启动根目录快捷方式。
